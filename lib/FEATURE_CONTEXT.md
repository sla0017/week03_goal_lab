# Feature Context - StudyGoal

## 학생이 이 파일에서 할 일

이 파일은 읽기 자료가 아니라 **코딩 전에 완성하는 작업지**다. 아래 순서대로 진행한다.

1. `완성 예시`를 읽고 문장의 형태를 확인한다.
2. `학생 작성 1~5`라고 표시된 다섯 곳만 자신의 문장으로 채운다.
3. `작성 확인`의 네 항목을 스스로 점검한다.
4. 파일명을 `FEATURE_CONTEXT.md`로 저장한다.
5. 맨 아래 `AI Agent에게 전달할 요청`을 복사해 Agent에게 보낸다.
6. 코드가 완성되면 앱에서 AC1~AC3를 실행하고 `실행 결과`를 기록한다.

강의 중 기능은 `StudyGoal 추가·완료 전환`으로 고정한다. 다른 앱이나 기능을 새로 정하지 않는다.

---

## 완성 예시

### 사용자 목표 예시

> 학생이 오늘 공부할 목표와 완료 여부를 한 화면에서 확인한다.

`SQLite를 사용한다`처럼 기술을 쓰지 않고, 사용자가 얻는 결과를 쓴다.

### 사용자 스토리 예시

> 앱프로그래밍을 배우는 학생으로서 나는 오늘의 학습 목표를 등록하고 완료 표시하고 싶다. 그래서 남은 학습 항목을 바로 확인할 수 있다.

### 수용조건 예시

> Given 목표 입력란이 비어 있을 때, When 추가 버튼을 누르면, Then 목록은 바뀌지 않고 `목표를 입력하세요`가 표시된다.

Given은 **시작 상태**, When은 **내가 한 행동**, Then은 **화면에서 확인할 결과**다.

## 내가 작성할 내용

### 학생 작성 1 - 사용자 목표

질문: 이 기능을 사용하면 학생이 무엇을 더 쉽게 확인하거나 할 수 있는가?

> [여기에 한 문장으로 작성]

### 학생 작성 2 - 사용자 스토리

아래 괄호를 바꿔 한 문장으로 완성한다.

> 앱프로그래밍을 배우는 학생으로서 나는 **[하고 싶은 행동]**하고 싶다. 그래서 **[얻게 되는 결과]**를 얻을 수 있다.

### 범위 - 읽고 확인 표시

다음 범위를 바꾸지 않고 읽은 뒤 `[x]`로 표시한다.

#### 이번 실습에서 만든다

- [ ] 1~20자의 학습 목표를 추가한다.
- [ ] 공백 입력을 차단하고 오류 문구를 표시한다.
- [ ] 목표를 완료 또는 미완료로 전환한다.

#### 이번 실습에서 만들지 않는다

- [ ] 로그인과 여러 사용자
- [ ] 서버 또는 데이터베이스 저장
- [ ] 알림과 일정 연동
- [ ] 앱 재시작 후 상태 복원

### 학생 작성 3 - AC1 정상 입력

- Given: 목표 목록이 비어 있고 `Dart 객체지향`이 입력되어 있다.
- When: **[사용자가 어떤 버튼을 누르는지 작성]**
- Then: **[목록에 어떤 내용과 상태가 보여야 하는지 작성]**
- Evidence: `evidence/ac1-valid.png`

### 학생 작성 4 - AC2 공백 입력

- Given: 목표 입력란에 공백만 입력되어 있다.
- When: **[사용자가 어떤 버튼을 누르는지 작성]**
- Then: **[목록과 오류 문구가 어떻게 되어야 하는지 작성]**
- Evidence: `evidence/ac2-empty.png`

### 학생 작성 5 - AC3 완료 전환

- Given: `Dart 객체지향` 목표가 미완료 상태로 목록에 있다.
- When: **[사용자가 무엇을 선택하는지 작성]**
- Then: **[체크 상태와 상태 문구가 어떻게 바뀌어야 하는지 작성]**
- Evidence: `evidence/ac3-complete.png`

## 작성 확인

- [ ] 사용자 목표에 패키지나 기술 이름 대신 사용자가 얻는 결과를 썼다.
- [ ] 사용자 스토리에 사용자, 행동, 이유가 모두 들어 있다.
- [ ] AC1~AC3의 When은 사용자의 행동이고 Then은 화면에서 볼 수 있는 결과다.
- [ ] 포함 범위 밖의 기능을 추가하지 않았다.

네 항목을 모두 확인했으면 이 파일을 저장하고 다음 요청을 AI Agent에게 전달한다.

## AI Agent에게 전달할 요청

```text
FEATURE_CONTEXT.md와 lib/main.dart를 읽어라.
먼저 AC1, AC2, AC3를 각각 한 줄로 요약하라.
_addGoal의 각 부분이 AC1과 AC2를 어떻게 만족하는지 설명하라.
그다음 AC3만 만족하도록 _toggleGoal의 TODO를 구현하라.
새 패키지, 로그인, 서버 저장, 화면 추가는 금지한다.
_addGoal은 AC1이나 AC2와 어긋나는 경우가 아니면 수정하지 마라.
수정 후 flutter analyze를 실행하고 AC별 수동 확인 방법을 알려 줘.
```

Agent가 AC를 잘못 요약하면 코드를 수정하게 두지 말고 이 문서의 문장부터 고친다.
